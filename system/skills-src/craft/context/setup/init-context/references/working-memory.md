# Working Memory Protocol

Last updated: 2026-08-16

Deep reference for the Working layer. Load when setting up or maintaining working memory.

The Working layer answers: *how is the current effort going, and what happens next?* It is git-ignored and discarded with the effort. Everything here is scaffolding; the Human and Core layers are the building.

---

## The boundary

**Durability test.** Before writing anything persistent: *if the work root were deleted today, would the project lose a fact it still needs?*

- Yes → belongs in Human or Core, not here.
- No → belongs in Working.

| Belongs in Working | Belongs in Human / Core |
|---|---|
| Discovery drafts and the conversation that produced them | Product intent — persona, job, demand verdict, scope commitments, Not-To-Do list |
| The plan for changing an architectural boundary | The boundary itself and its rationale |
| The options considered while writing an ADR | The settled ADR |
| The refactor in progress | The convention it establishes |
| Task claims, status, blockers, progress log | How to operate and deploy the system |

Promotion is one-way: Working → Human or Core. Never down. When a fact is promoted, keep a link in the working artifact — never a copy.

---

## Work root

Default: `.scratch/` at the repo root (recorded in `docs/agents/memory.md` under `Work root:`).

```text
<work-root>/<effort>/
├── state.md           ← routing hub; routes, does not store
├── progress.md        ← append-only session log
├── specs/             ← earned on first multi-ticket initiative
│   └── NNN-slug.md    ← one file per design initiative
├── tasks/             ← one file per atomic work item
│   └── NNN-slug.md
├── discovery/         ← optional: product discovery drafts
├── research/          ← optional: spikes
└── roadmap.html       ← generated by scripts/gen-roadmap.py; never edit directly
```

**Create only artifacts earned by the workflow.** `specs/` is not scaffolded — create it on the first multi-ticket initiative. Use the branch name as the `<effort>` slug when one exists.

## Three-layer structure

| Layer | Files | Purpose |
|---|---|---|
| Effort | `state.md`, `progress.md` | Current posture, next action, session history |
| Spec | `specs/NNN-slug.md` | Design intent for one initiative: why, criteria, topology |
| Task | `tasks/NNN-slug.md` | Single atomic unit owned by one agent or human |

Most efforts have 0–2 specs. Simple one-off work lives in `tasks/` only.

---

## `state.md`

```markdown
# <Effort> — State

Last updated: YYYY-MM-DD

## Status
<Posture in one or two sentences — not a task list.>

## Next action
<The single next concrete step, specific enough to start without re-deriving.>

## Blockers
<What is preventing progress. "none" if nothing.>

## Pointers
- Specs: `.scratch/<effort>/specs/`
- Tasks: `.scratch/<effort>/tasks/`
- Progress: `.scratch/<effort>/progress.md`
```

Update at the end of every session. `## Next action` must be specific enough that a cold session can start without reading anything else.

---

## `progress.md`

Append-only, newest on top, one entry per session.

```markdown
## YYYY-MM-DD — <one-line session summary>
<What happened, decided, deferred. 3–6 lines. Cite key file paths.>
```

Never rewrite history. Never delete an entry, even if the work was reverted.

## Spec format (`specs/NNN-slug.md`)

```yaml
---
id: "auth-refactor"
title: "Auth middleware refactor"
state: in-progress      # backlog | in-progress | done
topology: workflow      # workflow (default) | dag
---
```

```markdown
## Why
<Problem and motivation.>

## Acceptance criteria
- [ ] ...

## Design notes
<Key decisions and architecture sketch.>
```

`topology: workflow` — sequential steps, renders as a horizontal strip.  
`topology: dag` — parallel tracks with merge points, renders as a layered graph.  
Auto-detected as `workflow` when every task in the spec has at most one `depends_on`.

---

## Task format (`tasks/NNN-slug.md`)

```yaml
---
id: "003"
title: "Implement auth middleware"
spec: "auth-refactor"   # omit for standalone tasks
type: agent             # agent | human
state: ready            # see state machine below
depends_on: ["001", "002"]
claimed_by: ~
verify: "pytest tests/auth/ -q"
---
```

Body: context, constraints, acceptance detail.

---

## Task state machine

```
backlog ──► ready ──► claimed ──► in-progress ──► review ──► done
                                       └──► blocked ──► ready
                                                   review ──► in-progress  (verify failed)
any ──► abandoned
```

| Transition | Rule |
|---|---|
| `backlog → ready` | All `depends_on` tasks are `done` |
| `ready → claimed` | Write `claimed_by` before touching anything |
| `in-progress → review` | Work submitted — agent sets state, **never directly to `done`** |
| `review → done` | `verify` command passes — the only path to `done` |
| `review → in-progress` | Verify fails — reopen; log failure in `progress.md` |
| `→ abandoned` | Explicit decision; log reason in task body and `progress.md` |

**Triage rule:** scan `tasks/` for `state: ready` with no `claimed_by`, ordered by numeric id. Claim before editing.

## Promotion

| Found in working memory | Promote to | Via |
|---|---|---|
| Durable product intent (persona, scope, Not-To-Do) | `docs/product/<slug>/prd.md` | `write-prd` |
| Settled architectural constraint | `docs/ARCHITECTURE.md` | `document-codebase` |
| Technology choice and rationale | `docs/TECH_DECISIONS.md` | `document-codebase` |
| Durable trade-off with alternatives | `docs/adr/` | `domain-modeling` |
| Pattern the next contributor must follow | `docs/CONVENTIONS.md` | `extract-rules` |

A decision qualifies when it is settled, hard to reverse, and would surprise someone who did not watch it happen. Move the fact; leave a link in the working artifact pointing to its new home.
