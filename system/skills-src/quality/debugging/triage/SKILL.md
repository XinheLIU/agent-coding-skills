# Triage

Last updated: 2026-08-02

Read `docs/agents/memory.md`, tracker configuration, triage-label mapping, domain memory, and prior notes.

Use one category (`bug` or `enhancement`) and one state:

- `needs-triage`
- `needs-info`
- `ready-for-agent`
- `ready-for-human`
- `wontfix`

Gather the full request and code context. Check redundancy and prior rejection. Verify the claim before grilling: reproduce bugs; check that attached code does what it claims. Recommend a transition and wait for maintainer direction before mutating an external tracker.

A ready brief records objective, verified evidence, acceptance criteria, constraints, relevant memory pointers, checks, and explicit exclusions. Prefix AI-authored tracker comments with `> *This was generated by AI during triage.*`.

Locally tracked issues use the configured work root. Generated implementation tickets are already agent-ready and do not re-enter triage.
