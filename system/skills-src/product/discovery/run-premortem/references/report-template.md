# Pre-Mortem Record Mapping

Last updated: 2026-09-09

Use [the product memory contract](product-memory.md). Preserve the six-phase reasoning method, then enrich shared HTML records rather than generating a separate report. Read existing risks and related gaps first.

| Analysis | Shared memory contribution |
| --- | --- |
| Failure vision | A clearly labeled hypothetical narrative attached to the assessed plan/risk context. Invented dates, metrics, and quotes are never evidence. |
| Product-thread stress | The user's vision / demand / MVP-fit / discovery answers as assumptions or questions linked to the records they challenge; a missing vision or demand record as an open question. |
| Causes of failure | Match risk records by affected subject, trigger, and consequence; add distinct scenarios, dimensions, probability/severity rationale, and evidence or assumption links. |
| Top red flags | Link the highest-scoring risk IDs with brief labels; do not repeat their full analysis. |
| User confirmation | Confirmed readings cite the user's confirmation; disputed scores or causes carry both readings and the observation that would settle them. |
| Vaccine plan | Enrich the same risks with mitigation proposals, milestones, and responsible roles when known. Accepted mitigations cite the decision basis. |
| Pivot or revised roadmap | Proposed scope decisions linked to risks and existing capabilities. Cuts and new constraints remain proposed until authorized and reconciled by the scope skill. |
| Monitoring | Shared metric records with warning signal, threshold when established, response, and linked risks. |
| Final assessment | Concise interpretation and next action referencing the risk and question records that determine it. |

Each risk needs a concrete failure chain and an explicit basis for its score. Use the skill's scoring scale, keep unsupported estimates distinguishable from observation, and preserve contrary evidence. Reuse existing risk IDs when enriching a scenario; changing wording is not a new risk.

Record unresolved assumptions, questions, and behavioral gaps in their shared homes and link them. Do not close a gap because a mitigation was proposed or selected. Do not change demand grades from a hypothetical failure narrative. Record assessed coverage so a reader can distinguish "not assessed" from "assessed with no material finding."

Before handoff, verify unchanged scope remains intact, proposed actions are not presented as commitments, and repeated runs do not duplicate findings. Update the HTML and affected record dates, then `state.md` with relevant anchors.
