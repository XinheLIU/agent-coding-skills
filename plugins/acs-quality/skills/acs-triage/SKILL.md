# Triage

Last updated: 2026-09-25

## Context contract

```yaml
context:
  requires: [change.incoming_request]
  retrieves: [product.relevant_context, operations.constraints]
  produces: [change.triage_assessment]
  updates: [change.ticket_proposal]
  invalidates: [change.triage_dependents]
  handoff_to: [coordinator, product, implementation]
```

Shared semantics: [shared protocol](../../resources/skills-src/context/acs-init-context/references/PROTOCOL.md#skill-declarations); shared execution: [Coordination](../../resources/protocols/context-coordination.md). Apply their memory ownership and save-before-handoff rules; existing authorization persists. For human reports or review feedback, use [Presenter](../../resources/protocols/presenter.md); source records retain authority.


Read `docs/agents/memory.md`, tracker configuration, triage-label mapping, domain memory, and prior notes.

Use one category (`bug` or `enhancement`) and one state:

- `needs-triage`
- `needs-info`
- `ready-for-agent`
- `ready-for-human`
- `wontfix`

Gather the full request and code context. Check redundancy and prior rejection. Verify the claim before grilling: reproduce bugs; check that attached code does what it claims. Recommend a transition and return it to the coordinator, which applies already authorized tracker mutations or obtains missing authorization.

A ready brief records objective, verified evidence, acceptance criteria, constraints, relevant memory pointers, checks, and explicit exclusions. Prefix AI-authored tracker comments with `> *This was generated by AI during triage.*`.

Locally tracked issues preserve their configured tracker home; new local-only changes use tracked `docs/changes/<change-id>/`. Run scratch and claims use the work root. Generated implementation tickets are already agent-ready and do not re-enter triage.
