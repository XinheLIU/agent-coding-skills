Target Design

Refactor into 4 layers by authority, with purpose-specific CLI surfaces and unified change-set writes.

CLI Read: Answer-Shaped Views

Principle: CLI returns "me/project/team最近在忙什么" as a complete answer, not raw rows for the model to infer from.

horizon report me --since 4w
horizon report project <ref>
horizon report person <ref> --since 4w
horizon report team --week current

Server derives signals (overdue, no_worklog_3w) once. Model narrates, doesn't judge thresholds.

CLI Write: Single Change-Set Pipeline

Principle: One change-set file covers all CRUD ops. One version check, one consent, one audit record.

horizon plan diff --project <ref> --change-set cs.json
horizon plan preview --project <ref> --change-set cs.json
horizon plan apply --project <ref> --change-set cs.json \
  --preview-fingerprint <fp> --consent <token>

Replaces 16 individual write paths. Batch edits now expressible.

Skill Layer: Intent Only, Zero Facts

Principle: SKILL.md contains no value that migration could change.

horizon schema describe --output json
→ {statuses, projectNatures, codeFormats, ...}

Skill fetches schema on demand. 193-line SKILL.md → 60 lines.

Harness: Unforgeable Consent

Principle: Harness is the only layer that can distinguish "user said yes" from "model said user said yes".

plan preview returns consentChallenge. plan apply requires --consent <token> from harness approval flow.

Model can pass token but cannot mint it.

📍 Decision (2026-09-17): Single skill, not 4 separate skills

Context: impeccable v3.0 merged 17 skills → 1. Same judgment criteria apply here.

Rationale (4 criteria matched)
  • Description conflict: "what did I do last week" would trigger both horizon-report and horizon-worklog-entry

  • Shared reference: cli-contract.md needed by all 4 proposed skills
  • Enumerable commands: auth/context/report/plan/worklogs fit a Commands table perfectly
